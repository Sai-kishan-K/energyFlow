
# EnergyFlow 360 — Definition of Done

A User Story is considered Done only when:

## Functional Requirements

- All acceptance criteria are satisfied.
- Expected business behavior has been verified.
- Important edge cases have been tested.

## Code Quality

- The implementation is committed to Git.
- Code is readable and maintainable.
- No known critical defects remain.

## Testing

- Relevant automated tests pass.
- Regression tests pass.
- Invalid-input scenarios are covered.
- Test evidence is available.

## Documentation

- Functional specifications are updated.
- API or data contract changes are documented.
- Important decisions are recorded.

## Review

- The increment has been reviewed by the team.
- The agreed quality checks are satisfied.
- The Product Owner confirms story acceptance
  against its acceptance criteria.

## Release Readiness

- The feature is integrated.
- No blocking defects remain.
- The increment is usable in its intended context.

## Important Note

Product Owner acceptance confirms alignment with
business expectations. It does not replace the
Scrum Team's shared Definition of Done.

A story that does not satisfy the Definition of Done
must not be represented as complete.
